# 모아 · 나의 취업 사무실 — 초기 구현 v01

2026-10-06 PRD를 기반으로 만든 **이 컴퓨터에서만 사용하는 첫 버전**입니다. 개인 자료를 외부 AI나 채용 사이트로 보내지 않습니다. ‘모아’와 담당자 이름은 시안을 위한 임시 이름입니다.

## 열어보기

실행 중인 주소: <http://127.0.0.1:4317>

다시 실행할 때는 이 폴더의 **`시작.cmd`를 더블클릭**합니다. 이미 실행 중이면 같은 사무실을 엽니다. 서버는 이 컴퓨터의 루프백 주소에만 연결됩니다. 외부에서 접속할 수 있는 배포 주소가 아닙니다.

처음에는 가상 공고와 경험이 있는 **샘플 체험 공간**을 보여줍니다. 상단의 **‘내 사무실로’**를 누르면 실제 자료를 입력하는 빈 개인 공간으로 이동합니다. 두 공간의 저장 자료는 분리되어 있습니다.

권장 확인 순서:

1. 사무실의 **모리 · 자소서 쓰기** 이름표를 누릅니다.
2. 샘플 문항에서 경험을 선택하고 **‘선택한 경험으로 틀 채우기’**를 누릅니다.
3. 글을 수정하고 **‘새 버전 저장’**을 누릅니다.
4. 새로고침 후 글이 남아 있는지, **‘이전 버전’**에서 과거 글을 볼 수 있는지 확인합니다.

## 실제로 구현한 기능

- 생성한 밝은 픽셀 사무실 그림과 네 담당자의 클릭 가능한 이름표.
- 내 경험 등록·수정·검색·사실 확인 상태.
- 공고 링크에서 공개된 페이지 정보를 가져와 공고로 바로 보관. 회사·직무·마감일·원문·페이지에 공개된 자격 조건을 추출하며, 사이트가 자동 읽기를 막거나 정보가 부족하면 저장하지 않고 안내합니다. 직접 등록·수정도 가능합니다.
- Recruiter 채용 페이지의 공개 공고 정보도 읽습니다. 이미지로 된 상세 내용은 이 컴퓨터의 한국어 글자 인식 기능으로 읽어 본문에 저장하고, 명시된 지원자격·우대사항을 핵심 조건으로 모읍니다. 이미지에서 읽은 내용임을 표시하며 원문 이미지도 비교할 수 있습니다. 같은 링크로 다시 가져오면 기존 공고의 빈 본문·조건만 채우고, 작성한 내용·진행 상태·자소서 연결은 유지합니다.
- 공고 원문 이미지를 먼저 펼쳐 보여주고 그 아래에는 관심 직무 입력과 JD를 표시합니다. 해당 직무에 명시된 주요 업무·직무별 지원 자격·직무별 우대사항만 JD에 저장합니다. 공통 지원자격·공통 우대사항과 적용 직무가 불분명한 조건은 JD에 넣지 않습니다. 추출 본문과 전체 조건은 저장 자료로 보존하며 별도 화면 영역은 표시하지 않습니다. 이미지 없는 공고는 원문 글자를 표시하고, 공고 본문을 수정하면 JD를 다시 정리하라는 안내를 표시합니다.
- 공고별 여러 자소서 문항, 경험 선택, 글 구성·본문 편집, 글자 수, 새 버전 저장과 이전 버전 불러오기.
- 등록된 사실을 넣는 작성 틀. **AI 생성 초안이 아닙니다.**
- 단계별 프롬프트 등록·버전 관리·사용 버전 선택.
- 초안 프롬프트와 공고·선택 경험을 묶어 요청문 준비·복사. **자동 AI 실행은 아닙니다.**
- 회사·직무·지원일·상태를 직접 확인해 기록.
- 입력 조건의 단순 집계, 경험의 빈 역할·결과·확인 상태 점검. **AI 역량 분석은 아닙니다.**
- 개인/샘플 저장 분리, SQLite 영구 저장, 저장 버전 충돌 방지, 자료 백업·복원.
- 좁은 화면에서 메뉴 전환과 세로 배치, 키보드 접근, 저장 전 이동 확인.
- 로컬 전용 Chrome 확장 시험 패키지. 아래의 한계를 확인하세요.

## 아직 연결하지 않은 기능

- 실제 LLM API와 공고 해석·경험 추천·초안·퇴고·방향성 분석.
- 공고 링크 없이 자소설닷컴 공고를 자동 수집하거나 정기 실행하는 기능.
- 실제 기업 채용 사이트의 기본 정보 자동 입력·제출 감지.
- 외부 자소서 수집. 이 기능은 PRD에서 보류됐으며 이번 확장에도 포함하지 않았습니다.
- 실제 제출본의 자동 확보. 웹에서 작성한 버전이 외부 최종 제출본과 같다고 처리하지 않습니다.
- 자료 삭제·공고/경험 수정 이력 전체 관리, 공고 수집본 비교, 온라인 인증·공개 배포.
- 캐릭터의 개별 동작 애니메이션. 이번 사무실은 한 장의 생성 그림에 작업별 버튼을 연결한 방식입니다.

## 자료 저장

- `.data/moa.sqlite`: 실제 자료와 샘플 자료를 서로 다른 공간으로 저장.
- `.data/extension-token`: 로컬 확장 시험용 연결 코드. 공유하지 않습니다.
- 브라우저 저장에는 현재 선택한 공간 같은 화면 설정만 남깁니다.
- `.data`와 `.env`는 소스 관리에서 제외되며 서버에서 파일로 제공하지 않습니다.
- 백업은 설정 → 자료 보관 → 내보내기에서 받을 수 있습니다. 개인 자료가 들어 있으므로 직접 보관하세요.
- 복원은 현재 공간의 자료를 바꾸므로 기존 자료를 먼저 백업하세요. 잘못된 구조의 파일은 저장 단계에서 거부합니다.

## 개발 환경

- Node.js 24 이상.
- React + Vite 화면, Node HTTP 서버, Node 내장 SQLite.
- 개인용 로컬 구현으로 PRD의 기술 후보를 단순화했습니다. Next.js 또는 온라인 운영 방식은 아직 확정하지 않았습니다.

### 자기소개서 문항 추가

- `문항 추가하기`에서 공고를 선택하고 문항을 하나씩 추가합니다. 각 문항에 글자 수 제한과 공백 포함/제외를 따로 설정하며, 여러 문항을 한 번에 등록해도 답변·버전·피드백은 문항마다 독립적으로 저장합니다.
- 이미 문항이 있는 공고에는 이어지는 번호로 추가합니다. 작성 화면의 문항 버튼으로 같은 공고의 다른 문항을 선택할 수 있고, 저장해도 문항 순서가 바뀌지 않습니다.
- 글자 수를 초과하면 편집기·문항 목록·AI 초안 미리보기에서 초과 글자 수를 빨간색으로 표시합니다. 사용자의 요청에 따라 초과한 글도 그대로 저장할 수 있으며 자동으로 자르지 않습니다. 기존 문항과 본문은 유지합니다.

### 이미지 공고의 글자 읽기

- 공고 상세 상단의 `공고 삭제`에서 대상 회사·공고명을 확인하고 삭제할 수 있습니다. 연결된 자기소개서가 있으면 개수를 보여주며, 함께 삭제한다는 항목을 선택해야 진행됩니다. 공고/JD와 해당 자기소개서의 본문·버전·피드백을 함께 삭제하고 지원 현황 기록은 유지합니다. 삭제 중에는 중복 요청과 창 닫기를 막으며, 저장 성공 후 목록으로 돌아갑니다.

- 오뚜기 공식 채용 상세 페이지는 게시글의 실제 제목·모집 표·접수기간을 직접 읽습니다. 두 직무에 걸친 표의 자격조건은 해당 두 직무에 보존하고, 공고 이미지 주소도 함께 보관합니다. 본문이 이미 글자인 공고는 이미지 글자 읽기를 거치지 않으며 원문 글자도 표시합니다. 지원하지 않는 표 형식은 임의로 합치지 않고 오류로 안내합니다.
- 표시 보완(2026-10-07): 사용자가 지정한 오뚜기 64번 공고는 원문 게시글 영역 전체를 캡처한 이미지 한 장으로 표시합니다. 흩어진 작은 이미지와 표를 풀어 쓴 본문은 화면에서 대신 표시하지 않습니다. JD용 본문은 그대로 보존합니다. 이 이미지와 동일한 공고 주소·본문에만 적용되며, 원문이 바뀌거나 다른 글인 경우 기존 캡처를 재사용하지 않습니다. 모든 글을 자동 캡처하는 기능은 아닙니다.

- 한국어 OCR 언어팩이 있는 Windows에서 동작합니다. Node가 Windows PowerShell 5.1의 내장 Windows.Media.Ocr를 호출합니다. API 키나 외부 AI 전송은 필요하지 않습니다. [Microsoft OCR 문서](https://learn.microsoft.com/ko-kr/uwp/api/windows.media.ocr.ocrengine?view=winrt-26100).
- 공개 공고에서 확인한 같은 사이트의 HTTPS 이미지만 읽습니다. 이미지 한 장 12MiB, 전체 32MiB, 최대 12장까지 처리합니다. 긴 이미지는 원래 해상도의 세로 조각으로 나누며, 표의 구분선을 찾으면 인접한 열의 글자가 섞이지 않게 분리합니다. 원래 이미지의 글자·구분선 좌표를 함께 저장합니다.
- 추출한 글자는 저장되지만 인식 오류가 있을 수 있으므로 지원 자격과 숫자는 원문 이미지와 비교할 수 있도록 표시합니다. 이미지 읽기 실패·빈 결과·본문 60,000자 초과 시 일부 내용을 완전한 공고로 저장하지 않고 이유를 안내합니다.
- 원문 이미지 주소는 계속 보관합니다. 이미지 파일은 처리용 임시 파일만 사용하고 지우므로, 원문 사이트에서 이미지가 삭제되면 이미지 표시는 안 될 수 있습니다. 이미 저장된 추출 글자는 남습니다.
- 이전에 이미지로만 등록한 공고는 같은 링크로 다시 등록하면 빈 본문을 채웁니다. 상세 화면에는 원문 이미지와 관심 직무 JD를 표시합니다. 추출한 글자·공고 전체 조건 영역, 수동 이미지 글자 가져오기·다시 읽기 버튼과 JD 항목별 근거 펼쳐보기는 사용자 요청에 따라 표시하지 않습니다. 저장된 본문·조건·근거 자료는 보존합니다.
- 모집직무·전공·필수/우대사항 열과 구분선이 확인되는 표는 해당 행의 업무·전공·조건을 함께 발췌합니다. 다른 행의 조건은 공통 자격으로 넣지 않습니다. 글자 오류·구분선 없는 복잡한 표는 한계가 있으며, IT가 기호로 인식된 경우 같은 칸의 IT 업무가 함께 확인될 때만 연결하고 안내합니다.

```powershell
npm.cmd install
npm.cmd run dev
```

배포용 파일 빌드 및 로컬 실행:

```powershell
npm.cmd run build
npm.cmd start
```

자동 검사:

```powershell
npm.cmd test
```

`PORT`와 `MOA_DATA_DIR`로 서버 포트·시험 저장소를 지정할 수 있습니다. 시험 확장과 기본 실행기는 4317 포트를 사용합니다.
