# PRD: 픽셀 취업 사무실

> 내가 정리한 경험을 바탕으로, 작은 픽셀 사무실의 담당자들과 공고 이해부터 자기소개서 작성과 지원 기록까지 함께 진행하는 개인용 취업 지원 웹.

| 항목 | 내용 |
|---|---|
| 문서 버전 | v01 |
| 작성일 | 2026-10-06, 한국 시간 기준 |
| 프로젝트 위치 | `mini-project/` |
| 제품 이름 | ‘픽셀 취업 사무실’은 임시 이름이며 최종 이름은 미정 |
| 사용자 | 본인 1명, 기업 공채 중심으로 취업 준비 |
| 우선 관심 서비스 | 자소설닷컴. 실제 연동 가능 범위는 미검증 |
| 문서 상태 | 사용자 요청에 따라 작성한 상세 초안. 구현·서비스 연결·결제·배포는 승인하거나 실행한 상태가 아님 |
| 가장 중요한 사용 가치 | 공고를 이해하고, 내 경험을 골라, 해당 직무에 맞는 자기소개서를 작성하는 과정 지원 |

이 문서는 무엇을 만들고 어떤 결과가 나와야 하는지 정하는 설계도다. 대화에서 정한 방향을 구현 가능한 요구사항으로 풀었으며, 아직 정하지 않은 세부사항은 제안 또는 미정으로 표시한다.

### 결정 수준 읽는 법

- **확정:** 사용자가 직접 요청하거나 동의한 방향.
- **설계 제안:** 확정된 방향을 구현하기 위한 구체적인 기본안. 사용자 검토로 조정할 수 있다.
- **검증 필요:** 대상 사이트, 외부 서비스, 실제 자료로 확인해야 하는 사항. 가능 여부를 보장하지 않는다.
- **보류:** 이번 구현 범위에서 제외하되 아이디어를 유지하는 사항.

이하 기능의 세부 동작·데이터 구조·시험 기준·개발 순서는 별도 표시가 없으면 설계 제안이다. 기능 수준의 확정 여부는 4장의 표를 기준으로 한다.

## 1. 풀고자 하는 문제

### 1.1 현재 상황

- 사용자는 자신의 학력·경험·활동 등을 직접 정리한 자료를 제품에 등록해 활용하고 싶어 한다.
- 관심 직무의 공고를 보고 요구사항을 이해하는 일, 어떤 경험을 선택할지 판단하는 일, 경험을 설득력 있는 글로 만드는 일 모두에서 도움을 원한다.
- 반복되는 학력·연락처 등의 입력을 줄이고 싶다.
- 어떤 회사의 어떤 직무에 언제 지원했는지 별도로 정리하는 수고를 줄이고 싶다.
- 기업 공채 중심으로 지원하며, 자소설닷컴을 우선 연동 대상으로 생각하고 있다.
- 기존 자료의 실제 형식·양, 현재 사용하는 관리 도구, 작업에 드는 시간은 아직 확인하지 않았다.

### 1.2 문제와 해결 방향

| 문제 | 제품이 제공할 도움 | 피해야 할 결과 |
|---|---|---|
| 공고의 요구가 추상적으로 느껴짐 | 업무·필수 조건·우대 조건을 원문 근거와 함께 설명 | 근거 없는 ‘이 회사는 이런 사람을 좋아한다’ 단정 |
| 경험 선택이 어려움 | 등록된 경험에서 후보와 선정 이유를 제시 | 존재하지 않는 경험이나 성과 생성 |
| 경험과 직무의 연결이 어려움 | 문항별 주장·경험·구성 제안 후 초안 작성 | 그럴듯하지만 내 사실과 다른 글 |
| 무엇을 보완할지 막막함 | 공고와 경험의 차이를 설명하고 다음 행동 제안 | 불투명한 점수나 합격 확률로 능력 단정 |
| 지원서 기본 정보 입력이 반복됨 | 확인된 기본 정보를 지원되는 입력란에 채움 | 학력·학점 등을 추측해 잘못 입력 |
| 지원 내역 정리가 번거로움 | 제출 성공 근거를 확인해 회사·직무·지원일 기록 | 클릭이나 페이지 이동만으로 지원 완료 처리 |

### 1.3 제품 목표

1. 공고 1건을 중심으로 경험 선택부터 자기소개서 작성까지 끊김 없이 진행한다.
2. 사용자의 원래 자료, AI의 해석, 사용자가 확인한 사실을 구분한다.
3. 새로운 지원을 준비할수록 기존 경험과 작성 결과를 다시 활용하기 쉬워진다.
4. 자동 처리가 실패해도 수동 입력·복사·상태 확인으로 계속 진행할 수 있다.
5. 밝은 픽셀 사무실을 통해 각 기능의 역할과 진행 상황을 쉽게 이해한다.

### 1.4 제품이 보장하지 않는 것

- 합격, 채용 결과 예측, 객관적으로 검증되지 않은 직무 적합도 점수.
- 모든 채용 사이트의 자동 입력·자동 수집·제출 감지.
- 인터넷 전체의 공고를 빠짐없이 수집했다는 주장.
- 클릭만으로 사용자 대신 최종 지원서를 제출하는 기능.
- 사용자가 등록하지 않았거나 확인하지 않은 경력·성과의 사실성.

## 2. 사용자와 사용 환경

### 2.1 확정된 사용자

- 본인만 사용하는 개인용 도구다.
- 기업 공채를 준비하며 반복적으로 공고 분석·자기소개서 작성·지원 기록 확인을 수행한다.
- 여러 사람이 가입하는 서비스, 팀 협업, 공개 프로필, 유료 회원 기능은 현재 범위가 아니다.

### 2.2 환경 제안

- 주요 환경: PC 또는 노트북의 Chrome 브라우저.
- 웹: 사무실, 자료 관리, 공고 분석, 자기소개서 작성, 지원 현황을 제공한다.
- 확장 프로그램: 허용된 채용 페이지와 웹 사이에서 공고 가져오기·기본 정보 채우기·제출 감지를 담당한다.
- 작은 화면: 사무실 그림만 축소하지 않고 담당자 목록과 작업 창으로 전환한다. 휴대전화에서 확장 프로그램 기능까지 동작한다고 약속하지 않는다.
- 개인용이어도 외부에서 접근 가능한 주소로 운영한다면 본인만 접근할 인증이 필요하다. 로컬 실행 또는 온라인 비공개 운영 중 선택은 미정이다.

### 2.3 대표 사용 상황

| 상황 | 시작점 | 사용자가 얻어야 할 결과 |
|---|---|---|
| 처음 이용 | 직접 정리한 자료 등록 | 확인된 기본 정보와 경험 목록 |
| 공고 발견 | 주소·본문 입력 또는 확장 프로그램 | 회사·직무·요구사항이 정리된 공고 카드 |
| 자기소개서 준비 | 공고 카드에서 지원 준비 시작 | 문항별 경험 후보와 구성 |
| 초안 작성·수정 | 구성 확인 후 작성 요청 | 근거가 연결된 초안과 보존된 수정 이력 |
| 실제 지원 | 기업 지원서 화면 | 지원되는 기본 정보 자동 입력 |
| 제출 완료 | 지원 사이트의 접수 완료 표시 | 회사·직무·지원일이 남은 지원 기록 |
| 주간 방향 점검 | 관심 직무의 수집 공고 확인 | 강점·설명 보완·추가 확인·다음 행동 |

## 3. 입력 자료와 정보 사용 원칙

### 3.1 입력 자료

| 종류 | 입력 내용 | 최소 필요 항목 | 누락 시 처리 |
|---|---|---|---|
| 기본 정보 | 이름, 연락처, 학력, 전공, 재학·졸업 상태, 기간, 학점 기준 등 | 자동 입력하려는 항목에 해당하는 값 | 없는 항목은 비워 두고 누락 안내 |
| 경험 | 활동·프로젝트·인턴·수업·동아리 등의 직접 정리한 내용 | 경험 제목과 설명 | 구체적인 보완 질문 |
| 선호·목표 | 관심 직무, 신입·경력, 지역, 원하는 업무 | 방향성 분석에 사용할 관심 직무 | 초기에는 직접 선택한 공고만 분석 |
| 공고 | 공고 본문, 회사·직무, 주소, 마감 정보 | 분석 가능한 본문 | 주소만 저장하고 본문 입력 요청 |
| 자기소개서 문항 | 질문, 분량 제한, 기타 작성 조건 | 질문 본문 | 문항이 없으면 등록 요청 |
| 프롬프트 | 분석·경험 선택·구성·작성·퇴고용 지시문 | 해당 단계의 유효한 지시문 | 필요한 단계의 지시문이 없음을 안내 |

### 3.2 최초 자료 등록 방식

**확정:** 사용자 스스로 정리한 자료를 제품에 입력하고, 그 자료를 기반으로 작동한다.

**설계 제안:** 첫 버전은 텍스트 붙여넣기와 직접 편집을 기본으로 한다. AI가 내용을 항목별로 정리해 주더라도 사용자가 확인한 후 확정 자료로 사용한다. PDF·Word·이미지 자동 해석은 실제 보유 파일 형식을 확인한 뒤 지원 여부를 정한다.

등록 과정:

1. 사용자가 원문을 붙여넣고 자료 제목을 정한다.
2. 원문을 보존한 상태에서 기본 정보·경험 후보로 분리한다.
3. 각 항목에 ‘확인 필요’ 상태를 부여한다.
4. 사용자가 수정·확인한 항목을 저장한다.
5. AI 작업에는 확인된 사실을 우선 사용한다. 미확인 정보는 사실로 단정하지 않는다.

### 3.3 사실·해석·생성 문장의 구분

- **원문 자료:** 사용자가 실제로 입력한 내용.
- **확인된 사실:** 사용자가 사실로 확인한 역할·행동·성과 등.
- **AI 해석:** 이 경험이 어떤 역량을 보여줄 수 있는지에 대한 제안.
- **생성 문장:** 자기소개서 작성을 위한 표현. 생성됐다는 이유만으로 사실 자료에 추가하지 않는다.

보완 질문에 답한 내용도 저장 후보로 보여준 뒤 확인받는다. 예를 들어 ‘만족도 20% 향상’이 자료에 없으면 AI가 숫자를 채우지 않고 성과 확인을 요청한다.

### 3.4 외부 수집 범위

**확정:** 지원 내역의 초기 수집 항목은 회사·직무·지원일이다. 외부 사이트에서 자기소개서 문항·답변을 수집하는 기능은 보류한다.

- 확장 프로그램은 제출 전후에 자기소개서 본문을 수집·임시 저장·전송하지 않는다.
- 페이지 전체 HTML이나 화면 전체를 편의상 저장하지 않는다.
- 공고 본문 수집은 공고 분석을 위한 별도 기능이며 지원서 답변 수집과 구분한다.
- 중복 방지 및 출처 확인을 위해 공고 주소·사이트 공고 ID·감지 시각 등 최소 기술 정보 저장을 제안한다. 주소에 세션 정보나 개인 식별값이 있으면 제거·제외한다.
- 마감일은 공고에서 얻는 일정 정보이며 실제 지원일과 별개다. 날짜만 보이고 시간이 없으면 임의로 마감 시각을 확정하지 않는다.

### 3.5 AI 서비스로 전달할 정보

- 공고 분석에는 해당 공고와 관련 지시문을 전달한다.
- 경험 추천·자기소개서 작성에는 관련 경험과 문항을 추가로 전달한다.
- 이름·전화번호·이메일·주소 등은 작성 작업에 꼭 필요한 경우가 아니면 제외한다.
- 현재 필요한 자료만 선별하며, 모든 개인 자료를 매번 전송하지 않는다.
- 서비스 제공사, 보관 정책, 비용, 실행 위치는 실제 연결 전에 확인한다. 아직 개인 자료를 외부 서비스에 전송한 상태가 아니다.

## 4. 핵심 기능과 범위

### 4.1 기능 수준의 합의

| ID | 기능 묶음 | 결정 수준 | 이번 제품에서의 역할 |
|---|---|---|---|
| F1 | 내 자료·경험 관리 | 확정 | 모든 분석과 작성의 사실 기반 |
| F2 | 공고 수집·분석·방향성 안내 | 확정, 자동 수집 방식은 검증 필요 | 관심 직무의 요구와 내 보완 행동 안내 |
| F3 | 자기소개서 구성·작성·프롬프트 관리 | 확정 | 가장 중요한 핵심 기능 |
| F4 | 확장 프로그램의 기본 정보 자동 입력 | 확정, 사이트별 지원 범위 검증 필요 | 반복 입력 감소 |
| F5 | 지원 내역 기록·오늘 할 일 | 확정, 제출 자동 감지는 검증 필요 | 회사·직무·지원일 관리와 다음 행동 안내 |

공통 화면은 밝은 픽셀 사무실이며, 각 기능은 담당 캐릭터와 연결한다. 외부 자동화가 제한되더라도 각 기능의 수동 경로는 제공한다.

### 4.2 AI와 일반 프로그램, 사용자의 역할

| 주체 | 맡길 일 |
|---|---|
| AI | 공고 해석, 경험 연결 이유 제안, 보완 질문, 문항별 구성, 초안·퇴고, 방향성 설명 |
| 일반 프로그램 | 저장·검색·일정·글자 수 계산·버전 관리·지원되는 입력란 채우기·사이트별 완료 표시 감지 |
| 사용자 | 사실 확인, 경험 선택, 구성·초안 판단, 누락 정보 수정, 최종 제출, 불확실한 지원 상태 확인 |

캐릭터가 네 명이라고 서로 다른 AI 모델 네 개를 반드시 연결하지 않는다. 같은 모델을 역할별 지시문과 자료 범위로 나눠 사용할 수 있다. 실제 여러 AI 작업을 동시에 실행할 필요가 있는지는 구현 단계에서 판단한다.

### 4.3 전체 사용 흐름

내 자료 등록 → 공고 가져오기 → 공고 분석 → 경험 후보 확인 → 부족한 정보 답변 → 문항별 구성 확인 → 초안 작성·수정 → 외부 사이트에서 지원 → 기본 정보 자동 입력 → 사용자가 제출 → 완료 근거 확인 → 지원 내역 기록.

방향성 안내는 이 과정과 별도로 실행할 수 있으며, 관심 직무의 공고 묶음과 내 경험을 비교한다.

## 5. 결과물과 완료 조건

### 5.1 결과물

- 웹: 픽셀 사무실, 내 자료, 공고별 작업 공간, 자기소개서 편집, 지원 현황, 방향성 보고, 설정.
- Chrome 확장 프로그램: 공고 가져오기, 기본 정보 채우기, 선택한 사이트의 제출 감지.
- 저장 자료: 프로필·경험·공고·분석·웹에서 작성한 자기소개서 버전·프롬프트 버전·지원 기록.
- 코드와 개발 산출물의 기본 위치: `mini-project/`. 실제 개발 폴더 구조와 데이터 저장 위치는 실행 방식 결정 후 확정한다.
- 운영 중인 개인 자료는 소스 코드와 분리한다. Git 저장소 또는 공개 배포 파일에 포함하지 않는다.

### 5.2 제품 완료 판정 기준

1. 확인된 경험과 공고를 등록하고, 새로고침 또는 재접속 후 다시 열 수 있다.
2. 공고 분석 결과에 원문 근거와 필수·우대 조건의 구분이 있다.
3. 경험 후보에 실제 등록 경험의 연결과 추천 이유가 있다. 적합한 경험이 없으면 없다고 안내한다.
4. 사용자 선택을 거쳐 문항별 구성과 초안을 생성한다. 누락 사실을 꾸며 채우지 않는다.
5. 직접 수정한 글은 재생성으로 사라지지 않으며, 이전 버전과 사용한 프롬프트를 확인할 수 있다.
6. 지원하는 사이트·입력란에서 확인된 기본 정보만 채운다. 기존 입력값은 기본적으로 보존한다.
7. 회사·직무·지원일로 지원 기록을 저장하고 다시 찾을 수 있다.
8. 제출 클릭 후 실패한 경우 지원 완료로 기록하지 않는다.
9. 같은 접수 완료 표시의 반복 감지로 기록이 중복되지 않는다.
10. 방향성 안내에 사용 공고의 범위와 보완 행동, 판단 한계가 표시된다.
11. 캐릭터를 눌러 기능을 찾을 수 있고, 긴 글은 읽기 쉬운 작업 창에서 편집할 수 있다.
12. 자동 수집·입력 실패 시 사용자가 다음 행동을 알 수 있다.

‘지원 사이트에서 검증됨’과 ‘샘플 화면에서 검증됨’을 별도로 보고한다. 화면만 완성했거나 AI 모의 응답을 연결한 상태를 실제 AI·사이트 연동 완료로 표시하지 않는다.

### 5.3 실패 상태 표시

| 상황 | 화면 표시 예 | 사용자가 이어갈 방법 |
|---|---|---|
| 공고 읽기 실패 | 공고 본문을 가져오지 못했어요 | 본문 붙여넣기 |
| AI 연결 없음 | AI 연결 설정이 필요해요 | 저장·편집은 유지, 설정 열기 |
| AI 요청 실패 | 분석을 완료하지 못했어요. 입력 내용은 저장되어 있어요 | 다시 시도 |
| 경험 근거 부족 | 이 조건을 보여줄 확인된 경험이 없어요 | 경험 추가 또는 다른 후보 선택 |
| 입력란 인식 실패 | 이 항목은 자동 입력을 지원하지 않아요 | 값 복사 |
| 접수 성공 불확실 | 제출 여부를 확인해 주세요 | 완료 표시 확인 후 직접 상태 변경 |
| 기록 동기화 실패 | 이 기기에 임시 보관했어요. 연결 후 다시 저장할 수 있어요 | 중복 없이 재전송 |

## 7. 만드는 방식과 공유 방법

### 7.1 기본 구조 제안

**형태: 계속 사용하는 개인용 웹 + Chrome 확장 프로그램 + 필요한 작업의 LLM 연결.**

| 구성 | 쉬운 설명 | 책임 |
|---|---|---|
| 웹 화면 | 사용자가 보는 사무실과 작업 창 | 자료 입력, 검토, 편집, 기록 확인 |
| 서버 측 프로그램 | 화면 뒤에서 요청을 처리하는 프로그램. 내 컴퓨터 또는 별도 운영 환경에서 실행 | 저장, AI 요청, 비용·오류 관리, 확장 프로그램 연결 |
| 데이터 저장소 | 자료와 기록을 보관하는 장소 | 공고·경험·버전·지원 기록 보존 |
| Chrome 확장 프로그램 | 채용 페이지에서 동작하는 보조 도구 | 필요한 정보 추출, 입력란 채우기, 지원 완료 확인 |
| LLM API | 글을 이해하고 생성하는 AI 서비스와 연결하는 통로 | 해석·추천·작성 |
| 정기 실행 작업 | 정해진 시간에 수집·분석을 시작하는 기능 | 공고 갱신과 방향성 보고 |

### 7.2 기술 선택 제안

- 여러 화면, 저장, AI 요청을 다뤄야 하므로 단일 HTML 파일보다 웹 애플리케이션 구조를 제안한다.
- 후보: Next.js 계열 웹 구조, 개인 로컬 실행이라면 SQLite 같은 파일 기반 데이터 저장소. 온라인 운영이면 영구 저장과 접근 제어를 지원하는 저장소를 선택한다.
- 이는 확정된 기술 선택이 아니다. 실제 실행 환경, 설치 상태, 운영 방식 확인 후 정한다.
- UI·자료 저장부터 만들더라도 AI 연결부를 분리해 이후 제공사나 모델을 바꿀 수 있게 한다.
- API 키는 브라우저 화면·확장 프로그램 배포 파일에 넣지 않고 서버 측 설정으로 관리한다.

### 7.3 공유·운영 방식

- 개인용이므로 공개 배포는 기본 목표가 아니다.
- 선택지 A: 본인 컴퓨터에서 웹과 저장 프로그램 실행. 컴퓨터가 꺼지면 정기 작업이 실행되지 않을 수 있다.
- 선택지 B: 본인 인증이 있는 온라인 비공개 웹. 외부 운영 환경·저장·비용 확인이 필요하다.
- Chrome 확장 프로그램의 개인 설치와 스토어 공개 배포는 구분한다. 초기에는 개인 시험용 설치를 우선 검토한다.
- 외부 호스팅, 계정 연결, 실제 AI 결제, 스토어 등록은 이번 문서 작성에 포함하지 않는다.

## 11. 화면 구성과 픽셀 사무실

### 11.1 시각 방향

**확정:** 밝고 귀여운 픽셀 캐릭터, 각자의 자리와 담당 업무, 공간을 비스듬히 내려다보는 사무실 구도. 참고 이미지의 책상·캐릭터 배치를 참고하되 어두운 도서관일 필요는 없다.

**설계 제안:** 크림색 벽, 밝은 나무 바닥, 햇빛이 들어오는 창문, 연두·하늘색 소품. 기존 게임 캐릭터를 그대로 사용하지 않고 독자적인 캐릭터와 가구를 만든다.

- 공간과 캐릭터는 픽셀 표현을 사용한다.
- 긴 자기소개서 본문·입력칸·설명은 선명한 일반 한글 글꼴을 사용한다.
- 캐릭터 옆에 이름뿐 아니라 담당 기능을 함께 표기한다.
- 마우스 없이도 담당자와 주요 작업에 접근할 수 있게 한다.
- 움직임 줄이기 설정을 제공하고 반복 애니메이션이 글 편집을 방해하지 않게 한다.
- 배경음은 선택 사항이며, 구현하더라도 기본은 꺼짐을 제안한다.

### 11.2 담당자와 자리

아래 동물·이름·세부 소품은 확정하지 않은 예시다.

| 역할 | 자리 | 주요 동작 | 공유하는 자료 |
|---|---|---|---|
| 공고·방향성 담당 | 창가 게시판과 자료 더미 | 공고 가져오기, 요구사항 분석, 보완 행동 안내 | 공고, 관심 직무, 확인된 경험 |
| 경험 담당 | 책장과 정리함 | 경험 등록, 후보 추천, 추가 질문 | 사용자 자료, 경험 |
| 자기소개서 담당 | 컴퓨터와 스탠드 책상 | 구성·초안·퇴고·프롬프트 관리 | 선택 공고, 문항, 경험, 작성 버전 |
| 지원 관리 담당 | 서류함과 달력 | 지원 목록, 마감일, 기록 확인, 확장 프로그램 연결 | 회사·직무·지원일·공고 마감일 |

역할별로 자료를 따로 복제하지 않는다. 같은 공고와 경험을 함께 참조한다.

### 11.3 사무실 첫 화면

- 중앙 테이블: ‘이어서 준비하기’ 목록. 마지막 작업과 다음 행동을 표시한다.
- 일정 영역: 마감일이 가까운 공고와 확인할 지원 기록.
- 담당자: 클릭하면 해당 작업 창을 연다.
- 기본 메뉴: 내 자료 / 공고 / 자소서 / 지원 내역 / 방향성 / 설정. 사무실을 통하지 않고도 접근할 수 있다.
- 첫 사용: 자료 등록 안내를 보여주고, 샘플 체험은 실제 자료와 구분한다.

‘오늘 할 일’은 저장된 상태에서 만들며, 존재하지 않는 마감이나 외부 전형 결과를 AI가 추측해 추가하지 않는다.

### 11.4 작업 창

- PC: 사무실 옆 패널 또는 넓은 작업 창. 자소서는 전체 너비 편집 모드 제공.
- 상단: 현재 회사·직무·작업 단계.
- 본문: 입력 자료, 결과, 근거, 확인할 항목.
- 하단: 다음 단계로 진행 / 다시 생성 / 저장 등 현재 필요한 행동.
- 돌아가기: 입력·수정 내용을 잃지 않고 사무실로 돌아간다.
- 작은 화면: 사무실 대신 담당자 목록을 우선하며 기능 접근을 유지한다.

### 11.5 캐릭터 상태

| 상태 | 표현 | 실제 의미 |
|---|---|---|
| 대기 | 쉬기·책 정리 등의 작은 동작 | 진행 중 작업 없음 |
| 처리 중 | 자료 읽기·타자 치기 | 실제 요청이 진행 중 |
| 사용자 확인 필요 | 질문 말풍선 | 사실·선택·접수 여부의 확인 필요 |
| 완료 | 책상 위 결과 서류 | 결과 저장 성공 |
| 실패 | 재시도 안내 | 오류를 숨기지 않고 원인 범위 표시 |

서버 실패 중에도 영구히 작업 중인 듯 움직이지 않는다. 저장 실패를 완료 연출로 가리지 않는다.

## 12. F1 상세: 내 자료·경험 관리

### F1-01 원문 보존과 수정

- 원문과 정리된 항목을 연결한다.
- 사용자 편집은 변경 시점을 남긴다.
- 사실을 수정해도 과거 작성 결과가 조용히 바뀌지 않는다. 관련 결과에 ‘기반 자료가 변경됨’ 표시를 제안한다.
- 삭제 시 해당 경험을 참조하는 자소서가 있음을 안내한다. 단순 삭제와 관련 개인정보의 완전 삭제 범위를 구분한다.

### F1-02 경험 카드

필드: 제목, 활동 종류, 기간, 배경, 목표·문제, 내 역할, 행동, 결과, 배운 점, 증빙 링크, 확인 상태, 원문 연결.

모든 필드를 필수로 강제하지 않는다. 최초에는 제목과 설명만으로 저장하고, 공고에 활용할 때 부족한 정보를 질문한다.

### F1-03 보완 질문

- 추상적인 역량 선택 대신 실제 행동을 묻는다.
- 예: ‘팀워크 역량은 몇 점인가요?’보다 ‘의견이 달랐을 때 본인이 한 행동은 무엇인가요?’.
- 같은 사실을 이미 확인했다면 다시 묻지 않는다.
- 답변을 ‘경험에 추가’와 ‘이번 작성에만 사용’으로 구분할 수 있게 한다.

## 13. F2 상세: 공고 분석과 방향성 안내

### F2-01 공고 등록

- 입력 경로: 본문 붙여넣기 / 주소 입력 / 확장 프로그램에서 가져오기.
- 주소를 입력해도 로그인·접근 제한 등으로 본문을 못 읽을 수 있다. 실패하면 붙여넣기로 전환한다.
- 추출 후보를 회사·직무·본문·마감일·원문 주소로 보여주고 수정할 수 있다.
- 공고 게시일, 수집일, 마감일을 구분한다. 모르는 날짜는 미상으로 둔다.
- 같은 출처 ID나 정리된 공고 주소는 중복 후보로 확인한다. 회사·직무명만 같다는 이유로 자동 병합하지 않는다.
- 공고가 수정되면 새 수집본과 변경 시점을 남긴다. 이전 분석은 어느 수집본을 사용했는지 확인할 수 있다.

### F2-02 개별 공고 분석

결과 항목:

1. 실제 맡게 될 주요 업무.
2. 명시된 필수 자격과 우대 조건.
3. 보여주면 좋을 경험·성과·증빙.
4. 확인된 사실과 AI 해석의 구분.
5. 원문 인용 또는 해당 구간 연결.
6. 공고만으로 알 수 없는 사항.

특정 도구 이름이 자주 보인다고 반드시 가장 중요한 평가 요소라고 결론내리지 않는다. 공고의 업무 맥락과 필수·우대 구분을 함께 사용한다.

### F2-03 정기 수집

- 사용자 설정: 관심 직무, 신입·경력 구분, 수집 대상, 실행 주기, 최대 수집량.
- 실행 주기·상한은 아직 미정이며 실제 대상과 비용 확인 후 결정한다.
- 공식 제공 방식 또는 허용된 접근 경로가 있는지 먼저 확인한다. 로그인·접근 제한을 우회하지 않는다.
- 중복 공고를 제거하고, 새 공고·변경 공고·수집 실패를 구분한다.
- 부분 실패 시 ‘이번 결과는 수집 성공한 공고만 포함’임을 표시한다.
- 자동 수집을 설정하기 전에도 사용자가 모은 공고 묶음으로 방향성 분석을 실행할 수 있다.
- 자소설닷컴의 자동 수집 허용 범위와 구현 가능 여부는 아직 검증하지 않았다.

### F2-04 방향성 보고

분석 단위: 사용자가 선택한 관심 직무·경력 수준·기간·공고 묶음.

| 출력 | 설명 |
|---|---|
| 분석 범위 | 사용 공고 목록, 기간, 출처, 중복 제거 후 공고 수 |
| 반복 요구 | 어떤 요구가 몇 개 공고에 등장하는지와 근거 |
| 이미 보여줄 수 있는 부분 | 확인된 내 경험과 연결 |
| 설명을 보완할 부분 | 경험은 있으나 역할·성과·증빙이 부족한 경우 |
| 추가 확인할 부분 | 기록에 없어서 능력 유무를 판단할 수 없는 경우 |
| 다음 행동 | 경험 정리, 증빙 추가, 학습·작은 프로젝트 등 구체적인 제안 |
| 한계 | 표본 부족, 수집 실패, 직무 혼합 등 |

공고 수가 적어도 결과를 보여줄 수 있지만 ‘직무 시장 전체의 경향’으로 일반화하지 않는다. 반복 요구의 개수는 프로그램으로 대조하고 AI가 숫자를 임의 생성하지 않게 한다.

## 14. F3 상세: 자기소개서와 프롬프트

### F3-01 문항 등록

- 문항 내용, 분량 제한, 공백 포함 여부, 작성 조건을 등록한다.
- 외부 지원서의 문항 자동 수집은 초기 범위에서 제외한다. 사용자가 직접 입력할 수 있다.
- 글자 수는 프로그램으로 계산한다. 사이트가 바이트 등 다른 기준을 사용하면 차이를 안내하고, 실제 사이트의 최종 계산을 확인한다.

### F3-02 경험 추천

- 후보마다 경험 ID, 추천 이유, 연결된 요구사항, 부족한 정보, 다른 문항과의 중복 가능성을 표시한다.
- 후보가 없거나 약하면 적합하지 않음을 설명한다. 무조건 추천 개수를 채우지 않는다.
- 사용자는 추천을 바꾸거나 직접 경험을 선택할 수 있다.
- 경험 선택을 ‘그 경험의 모든 세부 사실 확인’으로 간주하지 않는다.

### F3-03 문항별 구성

- 문항이 묻는 것, 핵심 주장, 사용할 경험, 강조할 행동·결과, 문단 순서를 보여준다.
- 여러 문항에서 같은 경험을 쓰는 경우 알리되 무조건 금지하지 않는다.
- 사용자가 구성을 수정·확인한 후 초안 작성으로 진행한다.

### F3-04 초안·퇴고

- 초안은 선택 공고·문항·경험·프롬프트를 입력으로 생성한다.
- 사실이 빠졌으면 별도 확인 목록에 남긴다. 임의의 수치·회사 사정·직책을 만들어내지 않는다.
- 사용자가 전체 또는 선택 문단에 대해 수정 요청을 할 수 있다.
- 직접 수정한 버전과 AI 재생성 버전을 모두 보존한다.
- 웹 안에서 작성한 글은 저장·복사할 수 있다. 외부 제출본 수집이 보류됐다는 이유로 웹의 글 저장까지 제외하지 않는다.
- 외부 사이트에 붙여넣고 수정한 최종 내용은 자동으로 알 수 없다. 웹의 마지막 초안을 ‘실제 제출본’이라고 자동 명명하지 않는다.
- 사용자가 직접 ‘내가 제출한 버전’으로 지정하는 경우 ‘사용자 지정’ 출처를 표시한다.

### F3-05 프롬프트 관리

단계: 공고 분석 / 경험 선택 / 구성 / 초안 / 퇴고 / 방향성 안내.

- 사용자가 직접 작성한 프롬프트를 등록·수정한다.
- 사용자 프롬프트가 아직 없다면 해당 단계에 ‘프롬프트 준비 필요’를 표시한다. 기본 예시를 제공하면 사용자 작성본과 구분한다.
- 프롬프트에는 공고, 경험, 문항 등 들어갈 자료 자리를 지정할 수 있게 한다.
- 저장할 때 새 버전을 만든다. 현재 적용할 버전을 선택한다.
- 문법·필수 입력 누락을 실행 전에 확인한다.
- 같은 자료로 두 버전의 결과를 비교할 수 있게 한다. 비교 실행은 별도의 AI 사용량이 발생함을 표시한다.
- 새 프롬프트 적용이 과거 결과를 자동으로 다시 작성하지 않는다.

### F3-06 결과의 출처 추적

작성 결과마다 공고 수집본, 사용 경험과 수정 시점, 문항, 프롬프트 버전, 모델, 생성 시각을 연결한다. 사실 주장에 관련 경험을 연결해 사용자가 검토할 수 있게 한다. 연결이 있다고 사실성이 자동 보증되는 것은 아니다.

## 15. F4 상세: Chrome 확장 프로그램

### 15.1 확장 프로그램의 기본 화면

- 웹 연결 상태.
- 현재 사이트의 지원 여부.
- ‘공고 가져오기’.
- ‘내 정보 채우기’.
- ‘지원 기록 확인’과 선택 사이트의 자동 기록 켜기·끄기.
- 외부 자소서 저장 버튼은 초기 화면에 넣지 않는다.

### 15.2 사이트별 지원 표

| 대상 | 공고 가져오기 | 기본 정보 입력 | 제출 감지 | 현재 상태 |
|---|---|---|---|---|
| 자소설닷컴 | 우선 검토 | 실제 제공 화면 확인 필요 | 실제 제출 경로 확인 필요 | 미검증 |
| 연결된 기업 채용 홈페이지 | 개별 검토 | 사이트별 검증 | 사이트별 검증 | 대상 미정 |
| 미지원 사이트 | 수동 입력 경로 | 복사 경로 | 수동 기록 경로 | 자동 동작 보장 안 함 |

자소설닷컴에서 공고를 발견한 것과 실제 기업 홈페이지에서 제출한 것은 다른 사이트의 작업일 수 있다. ‘자소설닷컴 지원’이라는 한 표시로 두 영역을 모두 검증한 것처럼 표현하지 않는다.

### F4-01 공고 가져오기

- 사용자 클릭으로 현재 공고 페이지의 필요한 본문·정보를 읽는다.
- 회사·직무가 불명확하면 수정 가능한 후보를 보여준다.
- 지원서 작성 페이지에서는 본문 전체 추출을 실행하지 않는다. 인식하지 못한 페이지는 공고 본문을 직접 붙여넣도록 안내한다.
- 웹에서 저장이 끝나면 해당 공고 작업 공간을 열 수 있다.

### F4-02 기본 정보 자동 입력

1. 입력란을 찾고 등록된 기본 정보와 연결한다.
2. 항목별로 입력 예정 값, 기존 값, 인식 실패를 보여준다.
3. 사용자가 적용하면 확실히 연결된 항목을 입력한다.
4. 지원 사이트가 값을 받아들였는지 가능한 범위에서 다시 읽어 확인한다.
5. 실패한 항목은 복사해서 입력할 수 있게 한다.

- 기본값은 빈 입력란만 채우기다. 이미 작성한 값을 바꾸려면 구체적으로 선택한다.
- 학점과 만점 기준, 졸업 상태, 날짜 형식은 임의 변환하지 않는다.
- 학교 검색·복잡한 선택창·파일 첨부·자기소개서 입력은 항목별 지원 여부를 구분한다.
- 자동 입력이 성공해도 지원서의 최종 제출을 실행하지 않는다.
- 입력을 되돌릴 수 있는 범위는 같은 페이지의 변경한 기본 정보로 제한해 설계한다. 페이지 이동 후 복구까지 보장하지 않는다.

### 15.3 접근 권한과 연결

- 클릭 시에만 작동하는 기능과, 선택한 사이트에서 자동으로 제출을 감지하는 기능의 접근 범위를 구분한다.
- 자동 감지는 사용자가 허용한 사이트에서만 켠다.
- 웹과 확장 프로그램은 본인 연결인지 확인한다. 임의의 웹페이지가 저장된 프로필을 요청할 수 없게 한다.
- 사이트에서 추출한 글은 데이터로 처리한다. 그 안의 명령을 프로그램 지시나 프롬프트 설정 변경으로 실행하지 않는다.
- 브라우저에 모델 API 키를 저장하거나 노출하지 않는다.

## 16. F5 상세: 제출 감지와 지원 기록

### F5-01 임시 정보 확보

- 허용된 지원 사이트에서 제출 전 회사·직무를 확보하고 관련 공고와 연결한다.
- 처음부터 인식하지 못하면 사용자가 선택한 지원 작업 공간과 연결할 수 있다.
- 자기소개서 본문, 첨부 이력서, 지원서 전체 화면은 수집하지 않는다.
- 회사·직무가 서로 다른 탭의 정보와 섞이지 않도록 현재 탭·사이트·공고를 연결한다.

### F5-02 제출 성공 판단

- 버튼 클릭은 ‘제출 시도’의 근거다.
- 사이트별로 확인한 접수 완료 문구, 완료 화면의 구조, 접수 상태 등으로 성공을 판단한다.
- URL 변경, 페이지 로딩 완료, 단순 통신 성공만으로 접수 성공을 판단하지 않는다.
- 완료 표시가 명확해도 회사·직무를 식별하지 못하면 누락 항목 확인을 요청한다.
- 접수번호가 있다면 성공 판별에 일시적으로 활용할 수 있으나 원문 저장은 기본 수집 범위에 포함하지 않는다.

### F5-03 상태 전이

| 현재 상태 | 관찰·사용자 행동 | 다음 상태 |
|---|---|---|
| 작성 중 | 최종 제출 클릭 감지 | 제출 확인 중 |
| 제출 확인 중 | 실제 접수 완료 표시 확인 | 지원 완료 |
| 제출 확인 중 | 필수 항목 오류 등 명확한 제출 실패 | 제출 실패 |
| 제출 확인 중 | 시간 초과·탭 닫힘·확인 불가능 | 확인 필요 |
| 확인 필요 | 사용자가 접수 완료 확인 후 변경 | 지원 완료, 사용자 확인 출처 표시 |
| 제출 실패 | 수정 후 다시 제출 | 제출 확인 중 |
| 지원 완료 | 동일 접수 화면 재방문·새로고침 | 같은 기록 유지 |

확인 대기 시간은 실제 사이트 반응을 시험한 뒤 설정한다. 시간이 지났다는 이유로 성공으로 바꾸지 않는다.

### F5-04 지원일과 일정

- 사이트에서 실제 접수 시각을 제공하면 그 값을 우선 사용하고 출처를 남긴다.
- 제공하지 않으면 완료 표시를 처음 감지한 시각을 기록하되 ‘감지 시각 기준’으로 표시한다.
- 과거 접수 완료 화면을 나중에 열었다면 방문일을 과거 지원일로 단정하지 않고 확인을 요청한다.
- 사용자가 직접 지원일을 수정할 수 있다.
- 마감일, 지원일, 기록 생성일은 서로 다른 항목이다.

### F5-05 중복과 재지원

- 사이트 공고 식별자·공고 연결·감지 사건 식별값으로 중복을 확인한다.
- 동일 사건의 재전송에는 같은 식별값을 사용해 한 번만 저장한다.
- 같은 회사·직무라도 공고나 채용 차수가 다르면 별도 지원으로 보존한다.
- 취소 후 재지원처럼 구분이 어려우면 기존 기록과 함께 보여주고 확인받는다.
- 클릭 감지에서 실제 완료까지 시험할 때 실지원서를 시험 목적으로 제출하지 않는다. 모의 화면을 사용하거나 사용자가 원래 수행하는 실제 지원 과정에서 확인한다.

### F5-06 동기화 실패

- 웹과 연결이 끊기면 최소 지원 정보와 재전송 식별값만 임시 보관한다.
- 웹 저장 완료 전에는 ‘지원 기록 저장 완료’라고 알리지 않는다.
- 연결 복구 후 같은 식별값으로 재전송한다.
- 회사·직무가 불확실하면 수동 확인 대상 상태를 유지한다.
- 임시 정보의 삭제 시점과 보관 기간은 운영 설정으로 정하고, 저장 완료 시 불필요한 임시 정보는 정리한다.

### F5-07 지원 현황과 오늘 할 일

- 기본 목록: 회사, 직무, 지원 상태, 지원일, 공고 마감일, 원문·작업 공간 연결.
- 검색·필터: 회사, 직무, 상태, 기간.
- 직접 추가·수정·삭제 가능.
- ‘서류 검토 중·면접·합격·불합격·지원 취소’ 같은 후속 상태는 초기에는 사용자 수동 입력을 제안한다. 외부 전형 결과 자동 수집은 아니다.
- 다음 행동 예: 경험 선택하기, 초안 이어 쓰기, 마감일 확인, 지원 완료 여부 확인.
- 웹의 자소서 버전을 공고에 연결하되 실제 제출 내용과 같다고 자동 단정하지 않는다.

### 17.2 AI 실행 흐름

1. 사용자가 작업을 요청한다.
2. 서버 측 프로그램이 필요한 입력과 프롬프트 버전을 확인한다.
3. 관련 자료만 선별하고 불필요한 연락처 등은 제외한다.
4. AI에 요청하고 실제 진행 상태를 보여준다.
5. 결과 형식과 참조 경험·공고의 존재 여부를 확인한다.
6. 결과와 사용한 자료 버전을 함께 저장한다.
7. 근거 부족·검토 필요 항목을 표시한다.

원문 공고나 경험 자료에 포함된 지시는 분석 자료로만 취급한다. 사용자 설정 프롬프트와 구분한다. AI가 반환한 내용으로 임의 웹 방문·파일 삭제·지원서 제출을 실행하지 않는다.

### 17.3 작업 상태와 재시도

- 상태: 대기 / 실행 중 / 사용자 확인 필요 / 완료 / 실패 / 취소.
- 같은 버튼의 연속 클릭으로 동일한 유료 요청이 중복 실행되지 않게 한다.
- 사용자가 화면을 닫아도 저장된 결과를 다시 확인할 수 있게 한다.
- 취소 요청 후 이미 발생한 AI 사용량이 사라진다고 안내하지 않는다.
- 재시도 시 기존 결과를 보존하고 새 작업으로 구분한다.
- AI가 연결되지 않아도 기존 자료 열람·수정·지원 기록 관리는 유지한다.

### 17.4 비용 관리 제안

- 동일한 공고 수집본·경험 수정본·프롬프트 버전·모델 조합의 결과는 재사용할 수 있다.
- 입력이 바뀌면 기존 분석에 변경 알림을 표시하고 재분석을 선택하게 한다.
- 작업별 사용량을 기록한다. 공급자가 제공한 실제 사용량과 추정치를 구분한다.
- 앱에서 적용할 사용 한도와 초과 시 동작을 정한다. 한도는 아직 미정이다.
- 공급자의 알림·예산 설정이 실제 요청 차단인지 별도로 확인한다. 알림만 설정하고 비용이 반드시 차단된다고 설명하지 않는다.
- 주기적 작업의 실행 횟수와 재시도 횟수에는 상한을 둔다. 구체 값은 실제 시험 후 결정한다.

### 17.5 보존·복구·개인 정보

- 브라우저 임시 저장만으로 모든 자료를 보관하지 않는다. 영구 저장·백업·복구 방법을 함께 정한다.
- 개인용 자료 내보내기와 다시 가져오기를 제공하는 방향을 제안한다. 내보내기에 API 키 등 인증정보는 포함하지 않는다.
- 수정·재생성은 과거 버전을 보존하지만, 사용자의 명시적인 완전 삭제 요청은 관련 버전·사본까지 처리하는 범위를 안내한다.
- 운영 기록에는 원문 자소서·개인 연락처·인증정보를 불필요하게 남기지 않는다.
- 오류를 프로그램 자체, 실행 환경, 브라우저 권한, 외부 서비스 연결 문제로 구분해 안내한다.
- 모의 데이터, 실제 개인 자료, 자동 시험 결과는 구분한다.

| Q22 | 자료 수정 후 이전 자소서 열기 | 원래 결과 보존, 기반 자료 변경 알림 |
| Q23 | 키보드·작은 화면 사용 | 담당자와 주요 작업에 접근 가능, 글 잘림 없음 |
| Q24 | 모의 결과 화면 | 실제 AI 결과나 실제 제출 성공으로 표시하지 않음 |
| Q25 | 자료 내보내기·복구 | 주요 관계와 버전 복원, 인증값 제외 |

### 확인 수준 구분

- **자동 검사:** 상태 전이, 중복 방지, 저장·복구, 글자 수, 입력값 보존 등.
- **Codex 화면 확인:** 사무실 배치, 작업 창, 오류 표시, 실제 확인 가능한 연동 결과.
- **사용자 확인:** 캐릭터 분위기, 글쓰기 편의, 추천 경험의 적합성, 개인정보 처리 방식, 실제 제출 상태.

이 문서 작성 시점에는 위 시험을 수행하지 않았다. 실제 시험 결과는 이후 최상위 `작업일지.md`에 남기며, 모든 항목을 자동 검사로 대체했다고 주장하지 않는다.
