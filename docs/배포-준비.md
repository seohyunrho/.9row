# .9row 개인용 배포 준비

기준일: 2026-10-08. 범위: 현재 앱의 Vercel 실행 및 Supabase 영구 저장 준비.

## 사용자가 결정한 내용

- GitHub 저장소는 `seohyunrho/.9row`. 현재 작업본을 기준으로 관리한다.
- 첫 배포는 본인만 사용하는 개인용이다. 프로젝트 이름은 `.9row`를 요청했으며 생성 화면의 이름 허용 여부는 아직 확인 전이다.
- DB는 Supabase를 기준으로 준비한다. 실제 계정·DB 생성과 약관 동의는 별도 설정 단계이다.
- 첫 온라인 버전의 이미지형 공고는 원문 이미지 주소를 보관한다. 온라인 이미지 글자 추출은 추후 추가한다.
- 공통 조건을 제외한 직무별 업무·자격·우대, 문항별 자소서와 초과 시 빨간 안내/저장 허용을 유지한다.
- 기존 로컬 자료와 API 키는 자동으로 업로드하거나 이전하지 않는다.

## 실행 구조

브라우저 → Vercel Authentication → Vercel 서버 API → Supabase.

- 화면은 Vite가 만든 `dist`에서 제공한다. API는 루트 `api/[...path].mjs` 한 개의 함수로 처리한다.
- 로컬 `server.mjs`는 기존 SQLite를 계속 쓴다. Supabase 설정이 로컬 저장 방식을 자동 변경하지 않는다.
- Supabase의 `moa_workspaces` 테이블에는 `personal`, `demo` 두 행을 따로 저장한다. 기존 자료 형식을 JSON으로 보존한다.
- 자료 버전 번호가 같은 행만 변경하는 조건부 저장으로 여러 창의 덮어쓰기를 막는다. 충돌 시 409 오류를 반환한다.
- 서버 전용 Supabase 키만 DB 접근에 사용한다. 브라우저에 Supabase 키를 전달하지 않는다.
- SQL은 해당 테이블의 RLS(행 접근 제한)를 켜고 일반·로그인 사용자 권한을 제거한다. 서버 역할에 조회·추가·수정만 허용한다.

## 보안 경계와 켜는 순서

**Vercel Authentication / All Deployments가 사용자 인증을 담당한다.** 현재 앱에는 별도의 회원가입·앱 로그인 기능이 없다.

`MOA_ACCESS_POLICY`는 운영자가 보호 설정을 확인했다는 표시이며, 비밀번호나 로그인 기능이 아니다. 이 값만 설정하고 보호 기능을 끄면 앱 자료가 노출될 수 있다. 프로젝트 접근자는 본인으로 제한하고 공유 링크·우회 토큰·예외 주소를 만들지 않는다. 여러 사람이 쓰는 서비스로 전환할 때는 사용자별 인증·권한 분리가 먼저 필요하다.

1. 변경 코드를 GitHub의 별도 작업 가지에 보관한다. 실제 키·개인 자료·백업·예전 버전은 제외한다.
2. 사용자와 Supabase 프로젝트의 무료 요금제·지역·약관을 확인하고 빈 DB를 만든다. `supabase/migrations/202610080001_personal_workspaces.sql`을 적용한다. 기존 자료는 아직 옮기지 않는다.
3. Vercel 프로젝트를 연결한다. 첫 배포에는 `MOA_ACCESS_POLICY`와 실제 키를 등록하지 않아 API를 닫아 둔다.
4. Vercel Authentication을 **All Deployments**로 설정한다. 본인만 접근 가능하며 운영 주소·생성된 주소·미리보기 주소에 우회 예외가 없는지 확인한다.
5. 로그아웃 상태에서 화면 및 `/api/state`, 자료 수정, AI 요청이 보호되는지 확인한다. 이 확인 전에는 실제 자료와 키를 연결하지 않는다.
6. 아래 서버 설정을 **Production에만** 등록한다. `MOA_ACCESS_POLICY`는 보호 확인 후 마지막으로 넣는다. 설정 변경 뒤 다시 배포한다.
7. 가상 자료로 저장·새로고침·다른 창 충돌·재배포 후 유지·공고 이미지 보관을 확인한다. 이 코드 작성 단계에서는 해당 동작 검사를 실행하지 않았다.
8. 검증 후 기존 자료의 내보내기 파일을 별도로 백업하고, 사용자 승인 범위의 자료만 온라인 공간으로 복원한다. 자료 백업 파일을 GitHub에 올리지 않는다.

## Vercel 서버 설정

모든 값은 Vercel의 환경변수(실행 시 참고하는 설정값)에 등록한다. `VITE_` 접두어를 붙이지 않는다. 키 값은 채팅·문서·GitHub에 남기지 않는다.

| 이름 | 내용 |
|---|---|
| `SUPABASE_URL` | 이 앱 전용 Supabase 프로젝트 HTTPS 주소 |
| `SUPABASE_SECRET_KEY` | 서버 전용 새 Secret key. Publishable key가 아님 |
| `SUPABASE_SERVICE_ROLE_KEY` | 새 Secret key를 사용할 수 없을 때만 쓰는 기존 서버 키 대안 |
| `MOA_APP_ORIGIN` | 실제 운영 주소 하나. 경로나 마지막 `/` 없이 `https://…` |
| `MOA_ACCESS_POLICY` | 보호 확인 후 `vercel-authentication-all` |
| `GEMINI_API_KEY` | Gemini를 사용할 경우 서버에 등록하는 키 |
| `GEMINI_MODEL` | 계정에서 사용할 수 있는 모델 이름. 기존 기본값은 별도 지원 여부 확인 필요 |
| `MOA_DISABLE_EXTERNAL_AI` | `1`이면 외부 AI 요청 차단. 설정 중 개인 자료 전송 방지에 사용 가능 |

`VERCEL`, `VERCEL_ENV`, `VERCEL_URL`은 Vercel이 설정하는 값을 사용한다. 앱은 `VERCEL_ENV=production`만 받아들이며 preview API는 열지 않는다. 미리보기에 운영 키를 복사하지 않는다.

## 첫 온라인 버전의 범위

- 공고 링크의 글과 원문 이미지 주소 보관, 경험·프로필·자소서·버전·프롬프트·지원 내역 저장.
- 이미지형 공고는 이미지 글자 추출을 생략했다고 표시한다. 새 JD를 만들 글자 위치가 없으면 준비 중으로 안내한다. 로컬에서 이미 읽어 저장한 JD와 위치 자료는 유지된다.
- 원문 이미지 파일 자체를 Supabase Storage에 복제하지 않는다. 원문이 내려가면 이미지가 안 보일 수 있다. 별도 이미지 보관 기능은 추후 범위이다.
- Gemini 초안/검토는 서버에 키를 등록한 후 사용 가능하다. 온라인 화면에서 키를 입력하거나 서버 파일로 저장하지 않는다. 생성 요청문 전송 안내와 동의 절차를 유지한다.
- Chrome 확장 연결은 로컬 전용으로 유지한다. 온라인 API로 연결 토큰을 발급하거나 프로필을 전달하지 않는다.
- 홈 화면의 할 일은 기존처럼 브라우저 저장소를 사용한다. Supabase 동기화 대상이 아니다.
- DART·통합 자동 초안 흐름은 별도 기획 단계이다. 이번 배포 준비로 구현되는 기능이 아니다.

## 구현과 확인 범위

- 신규 코드: Supabase 저장 어댑터, 온라인 접근 전제 검사, Vercel API, DB 생성 SQL, 배포 설정.
- 화면: 온라인 키 관리 안내, 저장 위치 안내, 확장 로컬 전용 안내, 이미지 글자 추출 준비 중 표시.
- 설정 누락·미리보기 환경이면 자료에 접근하기 전에 요청을 거부한다. 외부 제공자의 오류 본문이나 키를 응답·로그에 남기지 않는다.
- 온라인 공고 수집은 실제 연결에 쓰는 DNS 주소도 공개 IP인지 확인한다. 주소 검사 후 내부 주소로 바뀌는 요청을 거부하고, 이동할 때마다 다시 확인한다. 기본 로컬 수집 방식은 유지한다.
- AI 동시 요청 제한은 함수 인스턴스별이다. 계정 전체 사용량 상한은 Gemini 제공자 설정에서도 관리해야 한다.
- 실제 Supabase 연결·SQL 적용·Vercel 배포·접근 보호·저장 지속성은 외부 설정 후 별도 확인이 필요하다. 실제 데이터나 키를 사용한 검사는 하지 않는다.
