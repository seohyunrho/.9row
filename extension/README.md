# 모아 · 지원서 입력 도우미 v0.2

S-OIL·HS효성·현대오토에버 공채 지원서에 저장한 기본 정보를 옮기는 입력 도우미입니다.
**일반 입력란의 입력 보조를 구현했습니다. S-OIL·HS효성·현대오토에버 로그인 후 실제 지원서의 전체 호환성은 아직 확인하지 못했습니다.**

## 설치 (최초 한 번)

1. 모아 사무실을 실행합니다. 기본 주소는 http://127.0.0.1:4317 입니다.
2. Chrome 주소창에 `chrome://extensions`를 입력합니다.
3. **개발자 모드**를 켜고 **압축해제된 확장 프로그램을 로드합니다**를 선택합니다.
4. 이 README가 있는 **extension 폴더**를 선택합니다. 상위 프로젝트 폴더나 versions 폴더가 아닙니다.
5. 이전 시험 버전이 이미 설치되어 있다면 해당 확장의 새로고침 버튼으로 업데이트합니다.

설치는 개발한 파일을 Chrome에서 직접 사용하는 방식입니다. 스토어 공개 배포는 하지 않았습니다.
Chrome의 버전에 따라 버튼 문구는 조금 다를 수 있습니다.

## 연결

1. 모아 웹에서 **내 정보 · 설정 → 연결 상태 → 연결 코드 복사**를 누릅니다.
2. 확장 아이콘을 누르고 **사무실 연결**을 엽니다.
3. 모아가 열린 주소를 선택합니다. 4317은 기본 앱, 4318은 별도로 실행 중인 디자인 시험 서버입니다.
4. 연결 코드를 붙여 넣고 **연결 확인**을 누릅니다. Gemini API 키를 넣는 곳이 아닙니다.
5. 연결 코드는 브라우저 종료/확장 재시작 때 지워지므로 그때는 다시 연결합니다.

## 사용

1. 본인이 지원하려는 S-OIL·HS효성 또는 현대오토에버 공고의 지원서 작성 화면에 로그인하여 학력 또는 자격증 영역을 엽니다.
2. 확장을 열어 **내 사무실의 실제 자료** 또는 **샘플 사무실의 가상 자료**를 고릅니다.
3. **저장한 기본 정보 불러오기** → 정보 종류 → 사용할 학교/자격증 등 기록 하나를 선택합니다.
4. **현재 페이지의 입력란 확인**을 누릅니다. 이 단계에서는 지원서에 값을 쓰지 않습니다.
5. 자동 연결된 값의 미리보기를 확인합니다. 항목별 수동 연결은 필요하지 않습니다. HS효성 학교명도 아래 자동 입력 버튼에 포함됩니다.
6. **자동으로 연결된 N개 입력**을 누르면 학교명 검색·정확한 결과 하나 선택·반영 확인 후 나머지 학적 정보를 이어서 입력합니다. 학교 결과를 최대 7초 동안 기다리며, 선택 후 새로 활성화된 입력란도 같은 기록의 저장값으로 연결합니다. 학교 선택에 실패하면 나머지 입력을 중단하고 이유를 알립니다. 회사 사이트가 입력 즉시 자동 저장할 수도 있습니다.
7. 실제 지원서에서 값이 유지됐는지 확인하고, 저장·제출은 본인이 진행합니다.

한 학교/자격증씩 선택합니다. 복수 항목의 추가 버튼, 사용자 정의 달력·선택창은 직접 조작합니다. HS효성 학교 검색에서 다른 캠퍼스나 같은 이름의 복수 결과는 임의 선택하지 않습니다. 전공은 검색어 입력까지만 지원하며 결과 선택은 사이트에서 합니다.
날짜 표기 변환을 임의로 하지 않습니다. 날짜 형식/학점 범위/일치하는 목록값이 다르면 건너뛰고 이유를 표시합니다.
직접 선택할 항목은 **선택한 기록 확인 · 값 복사**에서 값을 복사할 수 있습니다.

## 포함 / 제외

- 학력·자격증·프로젝트·해외경험의 짧은 기본 항목을 불러옵니다. 긴 활동 내용·메모는 제외합니다.
- 기존 입력값을 덮어쓰지 않습니다. 입력 직전에 바뀐 값도 다시 확인합니다.
- 이름·이메일·연락처, 비밀번호, 자기소개서, 동의 항목, 파일과 최종 제출 버튼은 다루지 않습니다.
- AI API 호출, 지원서 자동 제출, 실제 사이트 제출 감지·지원 기록 수집은 이 기능에 없습니다.
- iframe 안의 입력란과 읽기 전용 칸은 자동 입력하지 않습니다. 검색식 학교 선택은 진단 자료로 확인한 HS효성 결과 목록 구조에 한해 지원합니다.
- 대상은 `career.hyundai-autoever.com`, `recruit-apply.hyundai-autoever.com`, `hshyosung.recruiter.co.kr`, `s-oil.recruiter.co.kr`과 지정한 로컬 시험 페이지입니다. 다른 회사는 주소와 양식을 확인한 뒤 추가합니다.
- 채용 페이지 접근은 확장 아이콘을 누른 현재 탭에 한정합니다. 모든 사이트를 상시 읽는 권한은 없습니다.
- 프로필은 팝업 메모리에서만 쓰며 닫을 때 사라집니다. 연결 코드는 확장 전용 세션 저장소에 둡니다. 호스트 권한은 로컬 모아 서버 연결용입니다.

## 시험 화면과 검증 구분

http://127.0.0.1:4317/autofill-test.html 또는 실행 중인 시험 서버의 http://127.0.0.1:4318/autofill-test.html

왼쪽은 가상 지원서, 오른쪽은 확장과 같은 화면·입력 코드를 쓰는 **미리보기**입니다. Chrome 확장 API만 가상으로 대체합니다. 실제 확장 설치·권한·로그인 후 양식의 검증을 대신하지 않습니다.

- `npm test`: 연결 인증·허용 대상·정보 분리·기존 앱 검사를 수행합니다.
- 시험 화면 **입력 보호 검사 실행**: 11개 DOM 동작 검사를 수행한 뒤 가상 양식을 초기화합니다.
- `npm run build`: 실제 확장 소스를 미리보기에 반영한 뒤 앱을 빌드합니다.
- Chrome에 실제 설치한 확장은 로컬 시험 페이지에서도 사용할 수 있습니다. 우측 미리보기와 별도로 Chrome 도구 모음의 확장 아이콘을 열어 주세요.
- 실제 개인 자료를 가상 양식에 넣을 필요는 없습니다. 확장 실험에서는 샘플 공간의 가상 학력을 사용해 주세요.

## 기존 제출 감지 시험

이전 http://127.0.0.1:4317/extension-test.html 의 모의 제출 감지는 유지합니다.
확장을 4317에 연결하고 접힌 **기존 지원 기록 시험 → 4317 연결 코드를 시험에도 사용**을 누르면 기존 시험용 연결이 저장됩니다. 시험 기록은 샘플 공간에만 기록합니다. 새 기본 정보 입력과는 별개입니다.

## v0.2.4 · 학적 정보와 검색형 선택 보완 (2026-10-07)

- 짧은 학적 제목이 입력칸 옆에 분리되어 있거나 title로 지정된 경우 인식합니다. 학위구분·입학구분·졸업구분의 기본 radio 선택 항목도 연결합니다. 이미 선택된 항목은 유지합니다.
- 학교검색·전공검색 버튼을 찾아 별도 ‘검색 시작’ 동작을 제공합니다. 새로 열린 표준 dialog 또는 role=dialog/aria-modal 창에서 검색 입력칸이 하나일 때 저장된 이름을 넣고 검색합니다. 결과 확인 후 이름이 정확히 일치하는 선택 버튼이 하나일 때 사용자 선택으로 클릭합니다. 동일 이름이 여러 개면 직접 선택하도록 안내합니다.
- 이는 첨부 화면의 항목을 참고한 보완이며, HS효성의 로그인 후 HTML 구조를 확보한 전용 어댑터는 아닙니다. 비표준 팝업·새 창·iframe·검색 결과의 별도 선택 버튼·커스텀 드롭다운은 추가 구조 확인이 필요합니다. 학교·전공명을 일반 칸에 강제로 넣어 선택된 것처럼 처리하지 않습니다.
- ‘입학일/졸업일’ 칸에 저장된 YYYY-MM만으로 날짜를 만들어 넣지 않습니다. 정확한 날짜는 사용자가 입력해야 합니다. 학과계열·전공계열·본교/분교·주야간처럼 모아에 저장하지 않은 정보도 추정하지 않습니다.
- Chrome 확장 관리 화면에서 새로고침하여 버전0.2.4를 반영합니다. 연결이 초기화되면 기존처럼 모아4318에서 새 연결 코드를 복사해 연결합니다.
- 검증: 가상 DOM 자동 검사 및 /autofill-test.html의 ‘학적·학교 검색 시험으로 전환’. 실제 Chrome/HS효성 호환과 실제 저장은 별도 확인해야 합니다.

## v0.2.5 · 자동 연결과 구조 진단 (2026-10-07)

- 학교·대학·전공·학과의 내부 코드 항목은 스캔과 입력에서 제외합니다. 검색 결과 선택으로 사이트가 설정할 코드에 학교명을 넣지 않습니다.
- 일반 항목별 수동 연결 드롭다운을 제거했습니다. 의미가 확실하고 모아에 저장된 값이 있는 항목만 ‘자동 연결’ 값으로 보여 주며 한 번에 입력합니다. 중복·미확인·미지원 항목은 별도 접힌 목록으로 구별합니다.
- 검색에 사용할 이름이 하나면 선택창 없이 그 이름을 표시합니다. 주전공·복수전공처럼 후보가 여러 개일 때만 선택합니다.
- ‘지원서 구조 복사’는 모아 재연결이나 프로필 불러오기 없이 대상 채용 페이지에서 사용할 수 있습니다. 입력값·textarea·숨김 입력·비밀번호·페이지 URL/파라미터·자유 본문은 반환하지 않습니다. 학적 항목의 제한된 제목, 태그/종류, id/name/class/role 및 조상 요소의 구조, readonly/disabled 등만 복사합니다. 외부로 자동 전송하지 않으며 결과를 팝업에서 확인할 수 있습니다.
- 실제 HS효성의 사이트 전용 선택·읽기 전용 입력을 우회한 것은 아닙니다. 이 버전도 실제 회사 양식 전체 자동 입력 완료를 뜻하지 않습니다. 구조 진단을 바탕으로 실제 방식에 맞춰 추가 작업이 필요합니다.

## v0.2.6 · HS효성에서 확인된 학력 필드와 검색 구조 기록

- 사용자가 제공한 구조에서 highschool, college[n], graduateSchool[n]을 확인했습니다. 학력 기록의 학교 구분/학위로 입력할 구역을 나눕니다. 같은 종류가 여러 구역이면 임의로 첫 번째를 고르지 않습니다.
- score는 평점, perfectScore는 만점 기준으로 구별합니다. graduationTypeCode, entranceTypeCode, degreeTypeCode의 그룹 제목은 실제 name을 사용합니다. 비활성화된 칸은 활성화하거나 강제로 채우지 않습니다.
- div.search 안의 input[type=search]는 별도 팝업 대신 페이지 안 검색 입력으로 처리합니다. 같은 middle-set 안의 academyCode/majorCode로 학력 구역을 구별하고 코드값을 직접 수정하지 않습니다. 검색어 입력만 지원하며 실제 검색 결과 선택 처리는 구조 확인 전입니다.
- 검색 중 확장을 열면 목록이 사라지는 경우 ‘검색 결과 구조 기록 시작’을 먼저 누릅니다. 확장을 닫고 60초 안에 학교를 검색한 뒤 다시 ‘지원서 구조 복사’를 누릅니다. 검색 영역의 태그·클래스·역할·부모 관계만 기억하며 검색어/결과 문구/입력값/HTML은 기록하지 않습니다. 기록은 현재 페이지 메모리에만 남고 자동 관찰은60초 뒤 중단됩니다. 페이지 새로고침 시 없어집니다.
- 실제 자료 두 개의 비교: 항목은 모두66개, dialog는 모두0개, 학교검색 조상 div에 searched 클래스가 추가된 점만 달랐습니다. searched가 정확히 어떤 사이트 상태를 의미하는지는 사이트 코드 미확인입니다.
- 자동 검사59개 및 빌드 성공. 구조를 재현한 가상 DOM에서 구역 분리, 평점/만점 구별, 검색어만 입력, 목록이 닫힌 뒤 구조 보존과 개인 텍스트 제외 확인. 실제 HS효성 최종 입력/저장은 미검증입니다.

## v0.2.7 · 진단 수집/기록/복사 단계 구별

- 진단에는 숫자칸의 min/max/step 제한만 추가합니다. 개인 평점이나 입력값은 포함하지 않습니다.

## 0.2.24 — 계열 이름의 쉼표·가운데점 차이 처리
